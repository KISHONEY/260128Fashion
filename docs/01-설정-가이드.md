# 설정 가이드 (비개발자용)

이 문서만 따라 하면 **Supabase 가입 → 키 입력 → (선택) 내 컴퓨터에서 실행 → Vercel 배포**까지 마칠 수 있습니다.
화면 그림 없이도 따라 할 수 있도록, 눌러야 할 메뉴 이름을 **굵게** 적었습니다.

> 💡 서비스 화면은 가끔 바뀝니다. 메뉴 이름이 조금 다르면 비슷한 이름을 찾아 주세요.
> 예: “Project Settings” 가 “Settings” 로만 보일 수 있습니다.

전체 소요 시간: 약 40분~1시간 · 비용: 무료 요금제로 시작 가능

## 준비물

- 이메일 주소 1개 (교수님 계정용)
- [GitHub](https://github.com) 계정 — 소스 코드가 이미 저장소 `kisjeong/260128Fashion` 에 있습니다.
- 메모장 — 중간에 나오는 **주소와 키 3가지**를 잠시 적어 둘 곳

## 1단계. Supabase 가입하고 프로젝트 만들기 (약 10분)

Supabase 는 이 사이트의 **로그인, 데이터베이스, 파일 저장소**를 맡는 서비스입니다.

1. <https://supabase.com> 에 접속해 오른쪽 위 **Start your project** (또는 **Sign up**) 를 누릅니다.
2. **Continue with GitHub** 로 가입하는 것이 가장 간단합니다.
3. 가입 후 **New project** 를 누릅니다.
   - **Organization**: 기본값 그대로
   - **Project name**: `fashion-archive` (아무 이름이나 괜찮습니다)
   - **Database Password**: **Generate a password** 를 눌러 자동 생성 → 메모장에 복사해 두세요. (나중에 거의 쓰지 않지만 잃어버리면 곤란합니다)
   - **Region**: `Northeast Asia (Seoul)` 을 고르면 한국에서 빠릅니다.
   - **Create new project** 를 누르고 1~2분 기다립니다.

## 2단계. 데이터베이스 만들기 — SQL 붙여 넣기 (약 3분)

1. 왼쪽 메뉴에서 **SQL Editor** 를 누릅니다.
2. **New query** (또는 `+` 버튼) 를 누릅니다.
3. 이 저장소의 [`supabase/schema.sql`](../supabase/schema.sql) 파일을 열어 **내용 전체**를 복사합니다.
   - GitHub 에서 파일을 연 뒤 오른쪽 위의 **복사 아이콘(Copy raw file)** 을 누르면 한 번에 복사됩니다.
4. SQL Editor 의 빈 칸에 붙여 넣고 오른쪽 아래 **Run** 을 누릅니다.
5. 아래쪽에 `Success. No rows returned` 가 보이면 성공입니다.
   - “destructive operation” 경고 창이 뜨면 **Run this query** 를 눌러 진행하세요. (기존 정책을 지우고 다시 만드는 명령이 들어 있어서 뜨는 안내입니다)

> ✅ 이 SQL 은 여러 번 실행해도 안전합니다. 중간에 실패했다면 그냥 다시 Run 하세요.

이 SQL 이 만드는 것: 표(테이블) 13개, 권한 규칙(RLS), 알림 자동 생성, 비공개 파일 저장소(`archive`), 기본 카테고리 5개
(지속가능 패션, 의복 구성/패턴, 패션 트렌드, 소재/텍스타일, 패션 문화사).

## 3단계. 공개 회원가입 끄기 (중요! 약 1분)

아무나 가입하지 못하도록 막습니다. 학생은 교수님이 만든 **초대 코드**로만 가입합니다.

1. 왼쪽 메뉴 **Authentication** → **Sign In / Providers** (또는 **Providers**) 로 갑니다.
2. **Allow new users to sign up** 스위치를 **끕니다(OFF)**.
3. **Save** 를 누릅니다.
4. 같은 화면의 **Email** 항목은 켜진(Enabled) 상태 그대로 둡니다.

## 4단계. 교수님 계정 만들기 (약 2분)

> ★ **2단계(SQL)를 먼저 끝낸 뒤** 만들어야 합니다. 사이트에서 **가장 먼저 만들어진 계정이 자동으로 교수(관리자)** 가 됩니다.

1. 왼쪽 메뉴 **Authentication** → **Users** 로 갑니다.
2. 오른쪽 위 **Add user** → **Create new user** 를 누릅니다.
3. 교수님의 **이메일**과 사용할 **비밀번호**(8자 이상)를 입력합니다.
4. **Auto Confirm User** 에 체크합니다. (체크하지 않으면 인증 메일을 기다려야 합니다)
5. **Create user** 를 누릅니다.

확인 방법: **Table Editor** → `profiles` 표를 열면 한 줄이 생겼고 `role` 칸이 `admin` 이면 성공입니다.

## 5단계. 키 3가지 복사해 두기 (약 2분)

1. 왼쪽 아래 **Project Settings** (톱니바퀴) 를 누릅니다.
2. **Data API** (또는 **API**) 메뉴에서 **Project URL** 을 복사 → 메모장에 `URL:` 이라고 적고 붙여 넣기
   - 모양: `https://abcdefghijk.supabase.co`
3. **API Keys** 메뉴로 갑니다.
   - **Publishable key** (`sb_publishable_` 로 시작) 를 복사 → 메모장에 `공개키:` 로 적기
   - **Secret keys** 에서 기본 키를 **Reveal(보기)** 후 복사 (`sb_secret_` 로 시작) → 메모장에 `비밀키:` 로 적기
   - 화면에 “Legacy API keys” 만 보인다면 `anon public` 을 공개키로, `service_role` 을 비밀키로 쓰면 됩니다.

> ⚠️ **비밀키는 절대 다른 사람에게 보내거나 GitHub 에 올리지 마세요.** 이 키가 있으면 모든 데이터에 접근할 수 있습니다.
> 실수로 노출됐다면 같은 화면에서 키를 새로 만들고(Roll / Create new) 예전 키를 지운 뒤, Vercel 의 값도 바꿔 주세요.

## 6단계. (선택) 내 컴퓨터에서 실행해 보기 (약 15분)

배포 전에 미리 확인하고 싶을 때만 하면 됩니다. **건너뛰고 7단계로 가도 됩니다.**

1. <https://nodejs.org> 에서 **LTS** 버전을 내려받아 설치합니다. (설치 화면에서 계속 “다음”)
2. GitHub 저장소 페이지에서 초록색 **Code** 버튼 → **Download ZIP** → 압축을 풉니다.
3. 터미널을 엽니다.
   - Mac: `Spotlight(⌘+Space)` 에서 “터미널” 검색
   - Windows: 시작 메뉴에서 “PowerShell” 검색
4. 터미널에 `cd ` (cd 다음에 한 칸 띄움) 를 입력한 뒤, 압축을 푼 폴더를 터미널 창으로 **끌어다 놓고** Enter.
5. 폴더 안의 `.env.example` 파일을 복사해 이름을 `.env.local` 로 바꿉니다.
   - Mac Finder 에서는 `⌘+Shift+.` 를 누르면 점(.)으로 시작하는 숨김 파일이 보입니다.
6. `.env.local` 을 메모장(텍스트 편집기)으로 열어 5단계에서 적어 둔 값을 넣고 저장합니다.

   ```
   NEXT_PUBLIC_SUPABASE_URL=여기에 URL
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=여기에 공개키
   SUPABASE_SECRET_KEY=여기에 비밀키
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

7. 터미널에 아래 명령을 차례로 입력합니다. (첫 줄은 몇 분 걸립니다)

   ```bash
   npm install
   ```

   ```bash
   npm run dev
   ```

8. 인터넷 브라우저에서 <http://localhost:3000> 을 엽니다. 4단계의 교수님 이메일·비밀번호로 로그인되면 성공!
9. 끝낼 때는 터미널에서 `Ctrl + C` 를 누릅니다.

## 7단계. Vercel 에 배포하기 (약 10분)

Vercel 은 사이트를 인터넷에 올려 주는 서비스입니다. (무료 Hobby 요금제로 충분합니다)

1. <https://vercel.com/signup> 에서 **Continue with GitHub** 로 가입합니다.
2. 대시보드에서 **Add New…** → **Project** 를 누릅니다.
3. 저장소 목록에서 **260128Fashion** 옆 **Import** 를 누릅니다.
   - 목록에 없으면 **Adjust GitHub App Permissions** 를 눌러 이 저장소 접근을 허용하세요.
4. 설정 화면에서
   - **Framework Preset**: `Next.js` (자동 선택됨)
   - **Environment Variables** 를 펼쳐 아래 4개를 하나씩 추가합니다. (왼쪽 칸에 이름, 오른쪽 칸에 값)

     | 이름 (Key) | 값 (Value) |
     | --- | --- |
     | `NEXT_PUBLIC_SUPABASE_URL` | 5단계의 URL |
     | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 5단계의 공개키 |
     | `SUPABASE_SECRET_KEY` | 5단계의 비밀키 |
     | `NEXT_PUBLIC_SITE_URL` | 일단 `https://example.com` (배포 후 바꿉니다) |

5. **Deploy** 를 누르고 2~3분 기다립니다. 🎉 화면이 나오면 **Continue to Dashboard**.
6. 대시보드 위쪽 **Domains** 에 있는 주소(예: `https://260128-fashion.vercel.app`)를 복사합니다. 이것이 사이트 주소입니다.
7. 사이트 주소를 환경변수에 반영합니다.
   - **Settings** → **Environment Variables** → `NEXT_PUBLIC_SITE_URL` 의 `⋯` → **Edit** → 6번 주소로 바꾸고 **Save**
   - **Deployments** 탭 → 맨 위 배포의 `⋯` → **Redeploy** → **Redeploy**
8. Supabase 에도 사이트 주소를 알려 줍니다.
   - Supabase → **Authentication** → **URL Configuration**
   - **Site URL**: 6번 주소로 바꾸고 **Save**
   - **Redirect URLs** → **Add URL** → `6번주소/**` (예: `https://260128-fashion.vercel.app/**`) → **Save**

> 📌 Vercel 은 저장소의 **기본 브랜치**를 배포합니다. 나중에 코드가 바뀌어 GitHub 에 올라가면 Vercel 이 자동으로 다시 배포합니다.

### 배포 확인 체크리스트

- [ ] 사이트 주소로 접속하면 **로그인 화면**이 나온다
- [ ] 로그인하지 않은 상태에서 `사이트주소/research` 를 직접 열어도 로그인 화면으로 이동한다
- [ ] 교수님 계정으로 로그인하면 상단에 **관리** 메뉴가 보인다

이제 [첫 사용 가이드](02-첫-사용-가이드.md) 로 넘어가세요.

## (선택) 이메일 초대 · 멘션 이메일 알림 설정

**초대 코드만으로도 모든 기능을 쓸 수 있습니다.** 아래는 “이메일로 초대 링크 보내기”와 “멘션 시 이메일 알림”이 필요할 때만 하세요.

Supabase 기본 메일 발송은 **프로젝트 관리자 본인 주소로만, 시간당 몇 통**만 보낼 수 있어서 학생 초대에는 쓸 수 없습니다.
그래서 메일 발송 서비스(예: [Resend](https://resend.com), 월 3,000통 무료)를 연결해야 합니다.

### A. Resend 준비

1. <https://resend.com> 가입 → **Domains** 에서 학과·개인 도메인을 추가하고 안내대로 DNS 를 설정합니다. (도메인이 없다면 학교 전산팀에 문의하거나 이 기능은 건너뛰세요)
2. **API Keys** → **Create API Key** → 키(`re_` 로 시작)를 복사합니다.

### B. Supabase 이메일(SMTP) 연결 — 이메일 초대용

1. Supabase → **Authentication** → **Emails** → **SMTP Settings** → **Enable Custom SMTP** 켜기
2. 입력값
   - Sender email: `noreply@인증한도메인`, Sender name: `연구 아카이브`
   - Host: `smtp.resend.com`, Port: `465`
   - Username: `resend`, Password: A 에서 만든 API 키
3. **Save**

### C. 초대 메일 문구 바꾸기 (필수 — 이걸 해야 초대 링크가 동작합니다)

1. Supabase → **Authentication** → **Emails** → **Templates** → **Invite user**
2. **Subject**: `[연구 아카이브] 연구실에 초대되었습니다`
3. **Body** 를 모두 지우고 아래를 붙여 넣은 뒤 **Save**

```html
<h2>연구 아카이브에 초대되었습니다</h2>
<p>아래 버튼을 눌러 이름과 비밀번호를 정하면 가입이 완료됩니다.</p>
<p>
  <a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=invite&next=/auth/set-password"
     style="display:inline-block;padding:12px 20px;background:#171614;color:#ffffff;text-decoration:none">
    초대 수락하기
  </a>
</p>
<p style="color:#6d6860;font-size:12px">이 링크는 한 번만 사용할 수 있으며 일정 시간이 지나면 만료됩니다.</p>
```

### D. 멘션 이메일 알림 켜기

Vercel → **Settings** → **Environment Variables** 에 2개를 추가하고 **Redeploy** 합니다.

| 이름 | 값 |
| --- | --- |
| `RESEND_API_KEY` | A 에서 만든 API 키 |
| `EMAIL_FROM` | `연구 아카이브 <noreply@인증한도메인>` |

학생은 각자 **내 정보 설정**에서 이메일 알림을 끌 수 있습니다.

## 문제 해결

| 증상 | 해결 방법 |
| --- | --- |
| Vercel 배포 화면에 `환경변수 ... 가 설정되지 않았습니다` | 7단계 4번의 환경변수 이름 철자를 확인하고 Redeploy |
| 로그인했는데 계속 로그인 화면으로 돌아옴 | `profiles` 표에 내 줄이 있는지 확인 → 없으면 아래 “프로필이 없을 때” SQL 실행 |
| 교수 계정인데 **관리** 메뉴가 안 보임 | 아래 “교수 권한 직접 주기” SQL 실행 |
| 사진 업로드 시 “업로드 권한이 없습니다” | 2단계 SQL 이 끝까지 실행됐는지 확인 (Storage → Buckets 에 `archive` 가 있어야 함) |
| 초대 메일 링크를 누르면 “링크가 만료되었거나…” | C 의 메일 문구를 정확히 바꿨는지, 7단계 8번의 Site URL 이 사이트 주소인지 확인 |
| 이메일 초대 시 “초대 메일을 보내지 못했습니다” | B 의 SMTP 설정 확인. 급하면 **초대 코드**를 사용 |

**프로필이 없을 때** (SQL 을 실행하기 전에 계정을 먼저 만든 경우) — SQL Editor 에서 실행:

```sql
insert into public.profiles (id, display_name, role)
select id, split_part(email, '@', 1), 'admin'
from auth.users where email = '교수님이메일@example.com'
on conflict (id) do update set role = 'admin';
```

**교수 권한 직접 주기**:

```sql
update public.profiles set role = 'admin'
where id = (select id from auth.users where email = '교수님이메일@example.com');
```
